■ 진단 요약 — 왜 이 패치인가

 11/10 필드 실측에서 앱 라이브러리에 동일 곡이 두 개 기록됐다:

   - 퇴사할게여 (Narr. 기안84) / 소연 (SOYEON)  → 실패(빨간 !)
   - 퇴사할게여 (Narr. 기안84) / 소연           → 성공(24-bit ✓)

 곡·제공자(Amazon Hi-Res)·제목 괄호가 전부 같고 아티스트 문자열만
 달랐다. 즉 확장→앱 전달 표기의 라틴 괄호 병기가 앱의 이름 검색을
 깨는 것이 실패의 직접 원인(라이브러리 A/B로 확정). 제목의
 "(Narr. ...)" 괄호는 성공 카드에도 있었으므로 무해 — 손대지 않음.

■ 2.3.0 변경점 (2가지 + 2.2.9 로직 전부 유지)

1. 아티스트 라틴 괄호 병기 제거 (핵심)
   - 확장이 앱으로 곡을 넘기기 직전, 아티스트에서 괄호 안이 순수
     영문·숫자인 병기만 제거한다:
       소연 (SOYEON)               → 소연
       아이유(IU)                  → 아이유
       진영 (GOT7)                 → 진영
       너드커넥션(Nerd Connection) → 너드커넥션
   - 괄호 안에 한글이 있으면 그대로 둔다. BIG Naughty (서동현)는
     같은 실측에서 괄호가 붙은 채 성공한 케이스라 보존.
   - 원표기는 original_artists에 보존되고, 확장 내부 매칭 비교
     (isrcNorm)는 애초에 공백·괄호를 무시하므로 매칭 결과는 불변.

2. 제목 "한글+공백+조사" 오염 정리
   - 큐에서 "주저하 는 연인들 을 위해"(잔나비)처럼 페이지 마크업
     때문에 조사 앞에 공백이 섞여 전달되는 케이스를 전달 직전에
     정리한다 → "주저하는 연인들을 위해".
   - 원문은 original_name에 보존. "이 별로부터"처럼 원래 공백이
     맞는 제목은 규칙상 건드리지 않음(첫 글자 조사 제외).

■ 이번 패치로 회수가 기대되는 실패군 (11/10 라이브러리 기준)

   - 소연 (SOYEON) / 아이유(IU) / 진영 (GOT7) /
     너드커넥션(Nerd Connection) → 라틴 병기 제거 대상
   - 주저하는 연인들을 위해(잔나비) → 공백 오염 정리 대상

   ※ 다비치(타임캡슐)·10CM(너에게 닿기를)처럼 표기가 깨끗한데도
     실패한 곡은 이번 패치 대상이 아니다 — 원인이 제공자 등록
     표기·앱 리졸버 쪽이라 아래 협상 메모 사항이다.

■ 설치 절차 (2.2.9와 동일)

   1. 앱 설정 → 확장 → 기존 확장(bugs/melon/genie) 삭제
   2. 압축을 푼 폴더가 남아 있으면 폴더째 삭제
   3. 이 패키지의 .spotiflac-ext 3종 새로 설치
   4. 확장 정보에서 버전이 2.3.0으로 보이는지 확인
   5. 앱 재시작 한 번 (서비스 워커 초기화)

■ 테스트 감시 포인트

   - 실패했던 곡들이 큐에서 아티스트 괄호 없이 표기되는지
   - 13곡 고정 실패 집합이 몇 곡까지 회수되는지 (검증 기준)

     실패곡+분류
   - 다비치·10CM 등 잔여 실패는 실패로 두고 기록만 — 그쪽은 앱
     리졸버 협상 사항임
